title: The watcher opened every letter
slug: 2026-10-27-the-watcher-opened-every-letter
date: 2026-10-27
blog: yes
subtitle: A job-search agent reads two mailboxes every hour so no employer reply is missed. Its way of reading marked every message as opened, so the owner never saw anything new, and Gmail learned from the fake opens and flagged 88% of her mail as Important
concepts: the-read-that-writes, silent-failure, verify-from-logs, fate-sharing
symptom: The owner reported that every message in both of her mailboxes — Gmail and the company mailbox — already showed as read when she opened them, and that Gmail had put its blue "Important" marker on almost everything. A read-only audit of 14 days on the live mailboxes confirmed it exactly: 425 of 425 inbox messages were marked read, while 166 of 166 messages in the spam folders were still unread. The only thing that had touched the inboxes and not the spam folders was the agent that watches for employer replies.
root_cause: The reply detector opened each inbox in normal read-write mode and downloaded every message in full. Over IMAP, that kind of fetch sets the "seen" flag on the server, so every hourly scan stamped every new message as opened within the hour. The day the agent started reading Gmail (23 August), Gmail's share of read mail jumped from 55–68% in the months before to 100%, and it has stayed there. Gmail's own importance model learns from which messages the user opens; from the fake opens it learned that she opens everything, and its "Important" share climbed from about a third of her mail before 23 August to 61%, then 79%, then 88% in the last two weeks. The same audit found three quieter gaps in the same agent: it remembered messages by their position in the mailbox, which shifts when anything is archived; it read only the 50 newest messages per pass; and it never looked in spam, where eight LinkedIn notices that a real person had messaged her were sitting.
fix: Every mailbox and folder is now opened read-only and every message fetched with the side-effect-free form of the read, in the detector and in a second helper that had the same habit. Messages are remembered by their permanent ID instead of their position, the 50-message cap is gone, and both spam folders are scanned. The agent's memory file had also been loaded in a type no lookup could ever match, so after every restart it had forgotten what it had already judged; that was corrected too. The Important labels that the fake opens had produced were removed from the 1,320 messages received since 23 August, after their IDs were saved so the change can be undone; read state was left alone, because nobody can tell which of the old messages the owner had opened herself.
verified: First on a copy of the agent run against the live mailboxes, then on the first real hourly cycle after the deploy. The number of unread messages in all four folders was identical before and after the scan, including two Gmail messages that had arrived after the previous scan and stayed unread through it. The same cycle read both spam folders for the first time and surfaced one of the LinkedIn notices as a question for the owner. A new test fails the build if any code path opens a mailbox in read-write mode or fetches a message in a way that marks it read. A recount after the label clean-up found 0 of the 1,776 inbox messages since 23 August still carrying the Important label, with the unread counts unchanged.
rule: A watcher must not change what it watches. For anything that "only reads", prove it by measuring the state before and after it runs; if the numbers move, the read wrote. And when the state you touch is also someone else's training data, a side effect is a feedback loop.
