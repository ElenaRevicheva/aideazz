---
title: The threshold outlived its model
slug: 2026-11-03-the-threshold-outlived-its-model
date: 2026-11-03
blog: yes
subtitle: A family-language companion had chat history, semantic search over 588 stored conversation turns and a memory reader wired into every reply, and still forgot the people it talked to. The search cut-off had been tuned for a different embedding model, so real matches were thrown away, and nothing ever wrote down a fact about a person
concepts: calibration-drift, silent-failure, verify-from-logs, liveness-is-not-correctness
symptom: The owner had asked many times for the assistant to remember families, and it did not. The code looked complete. It kept the last five turns of each conversation in a database through LangChain, it embedded every turn for semantic search (retrieval-augmented generation, RAG), and a reader put "key memories about this user" into every reply. Production said otherwise. The table of facts about users held 13 rows after a year, 7 of them test entries. The RAG table held 588 embedded turns, yet the reply builder received nothing from it. An end-to-end test with a made-up family through the real code on the production database showed the break exactly: after the family said their son starts at a new school on Monday, the later message "today was my son's first day of school" retrieved no earlier turn at all.
root_cause: Two separate gaps, both silent. First, the semantic search kept only matches above a cosine similarity of 0.55. That number had been carried over when the embeddings moved from a paid API model to a free local multilingual model, whose scores for "the same topic" sit much lower. Measured on the test family, the related school turn scored 0.397, while unrelated turns scored 0.26 to 0.37. With the cut at 0.55 the search returned an empty string, which the reply builder treats as "nothing relevant", so no error and no log line ever appeared. Short bot replies such as "you're welcome" also scored as high as real content, crowding out what the person had said. Second, the fact memory had a reader and no writer: the only code that stored a fact about a user ran during an onboarding form almost nobody finished. Conversation history and semantic search remember sentences; neither one turns "my son Mateo is 8 and starts school Monday" into a fact the assistant can bring up a week later.
fix: The cut-off was set from measurement, not memory: 0.38, which keeps the related turn and drops the unrelated ones. Search now recalls what the person said rather than the assistant's own replies, skips turns already present in the five-turn history window so nothing is sent twice, and logs a line each time it recalls something. A missing writer was added inside the existing memory module: after each grown-up message a free model notes up to three lasting facts (family members and ages, city, school, upcoming appointments with their day), in a background thread so replies are not slowed, with duplicates skipped and identification numbers, phone numbers, addresses and bank details never stored. The reader was widened from five facts to ten. Both chat channels share the same memory code, so one change fixed both.
verified: Production database counts: 13 user facts (7 tests) and 588 local embeddings before the fix. The end-to-end test ran the real memory code against the production database with a made-up family and deleted every one of its rows afterwards. Before the change: the school message recalled nothing at the 0.55 cut, with measured scores of 0.397 for the related turn and 0.26 to 0.37 for unrelated ones. After: the same message recalled the school turn at 40%, "I got my residence card" recalled the immigration appointment at 72%, "how do I say outlet again?" recalled the earlier question about the Spanish word at 41%, and the fact writer stored three facts including the appointment, while a pure lesson question produced none and a phone number in a test message was skipped. Both services were redeployed with file checksums equal to the committed code and no errors after restart. Real families had not yet written since the deploy at the time of writing, so the live path is proven by the end-to-end test, not yet by traffic.
rule: A threshold belongs to the model that produced the scores. When the model changes, measure the scores again before trusting the cut, and test memory end to end with a known conversation, because an empty result looks exactly like "nothing relevant".
