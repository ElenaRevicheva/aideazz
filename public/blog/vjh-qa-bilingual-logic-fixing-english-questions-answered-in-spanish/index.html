VJH Q&A Bilingual Logic: Fixing English Questions Answered in Spanish

October 17, 2026 · by Elena Revicheva

My VibeJobHunterAIPA_AIMCF (VJH) bot recently answered an English question about job counts in Spanish. This wasn't a minor translation error; it was a fundamental breakdown in the expected bilingual logic. The underlying issue was that shared facts, half in Spanish, were influencing the language of the entire response, even when the user's input was clearly English. This led to a commit, 0215cb0, on 2026-10-16, specifically addressing how VJH Q&A handles language detection and response generation to ensure explicit language lines and honest counts.

This wasn't an isolated incident. The cto-aipa process, which VJH interacts with, has seen 216 restarts and has been up for 1 day. My algom-stream process has 55193 restarts over 62 days. These numbers highlight the continuous iteration and debugging required to keep these systems operational and accurate.

The Bilingual Problem: Shared Data and Implicit Language

The core of the VJH Q&A bilingual logic issue was that the bot's knowledge base contained a mix of English and Spanish data. When a user asked a question, especially one involving counts, the system would often default to Spanish if any part of the relevant data was in that language. This was particularly problematic for questions like "How many jobs are available?" where the answer, even if numerical, would be prefaced or followed by Spanish text.

The commit a2ecb38 (2026-10-16) was the first step, introducing a "language reminder right before the answer." This was a direct response to live proof showing an English question answered in Spanish because "the shared facts are half Spanish." The goal was to explicitly state the language of the answer, using Whisper's detected language when available, or "the language of her message" otherwise. Screenshots, however, kept their own rule.

Ensuring Honest Counts and Explicit Language Lines

The problem extended beyond just language. The bot was also giving "false 'complete' label" responses, where job counts were not fully accurate. The commit 5204521 (2026-10-16) tackled this by ensuring counts came directly from HubSpot totals in the deals sheet header. This meant parsing the old header but prioritizing the real, per-stage totals from HubSpot. My evals/test_qa_conscience.py suite was crucial here, with 17 failures on the old code and 0 on the new, specifically pinning the language reminder, the "AI working is not an interview" message, and honest counts.

The final piece of the puzzle came with 0215cb0 (2026-10-16). This commit refined the VJH Q&A logic:

  • A typed question with clear English or Spanish words now gets an explicit language line.

  • Mixed or unclear language inputs retain the generic line.

  • The "conscience test" now pins both scenarios, with 26 passes.

This change directly addressed the "English count question answered in Spanish, live 17:55" incident, ensuring that the bot's response language aligns with the user's explicit input, not just the language mix of the underlying data.

The Operator Queue: A Shared Memory for Disconnected Agents

The NOW.md file in cto-aipa/docs/oracle/ serves as the "working memory of whichever agent is not currently running." It explicitly states: "Cursor Cloud, Cursor Desktop and Claude Code all work this repo and none of them can see each other's chats." This means there's no shared conversation, no Claude MCP in Cursor, and no way to send messages between agents. The only shared elements are HubSpot and this NOW.md file. This protocol is critical for avoiding conflicts when multiple AI agents, like Cursor and Claude Code, are working on the same repository without direct communication channels.

Frequently Asked Questions

Q: How did the bot determine the language of the user's question for the VJH Q&A bilingual logic?
A: The system now explicitly checks for words in the typed question that clearly lean English or Spanish. If the language is unambiguous, it triggers an explicit language line in the response. If the input is mixed or unclear, a generic language line is used.

Q: What was the specific impact of the "half-Spanish data" on English questions?
A: Live proof showed that an English question, particularly one asking for counts, was answered in Spanish because the underlying shared facts relevant to the answer were partially in Spanish. This led to a user experience where the bot responded in an unexpected language.

Q: How did you verify the fix for "honest counts"?
A: The evals/test_qa_conscience.py suite was used. Before the fix, 17 tests failed. After the commit 5204521, all 17 tests passed, confirming that counts were accurately pulled from HubSpot totals in the deals sheet header.

Q: What is the purpose of the "language reminder right before the answer"?
A: This reminder, introduced in commit a2ecb38, explicitly states the language of the answer to the user. It uses Whisper's detected language if known, otherwise it defaults to "the language of her message," to prevent confusion when the bot's response language might differ from the user's expectation due to mixed data sources.
